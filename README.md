# Photorium：構圖輔助相機（Web 原型）

拍照時分析相機畫面，建議適合的構圖方式，讓使用者先預覽構圖再拍照。
這是用來**快速驗證想法**的網頁原型：不需要安裝 App，手機瀏覽器打開就能用。

**線上版（手機可即時取景）**：https://toolman47.github.io/photorium/

## 功能

- **即時取景分析**（每秒約 4 次）：主體位置與大小、水平線位置與傾斜角度、左右／上下對稱度、斜線方向
- **構圖建議與評分**：三分法、黃金比例（含螺旋線）、中央對稱、水平線三分、倒影對稱、大量留白、主體特寫、對角線
- **取景提示**：畫面上只有淡淡的參考線、目標圓圈和代表主體的黃點，移動手機讓黃點進入圓圈。上方一次只提示一個方向（例如「→ 手機往右」，前鏡頭自拍時方向也正確）。構圖到位時提示會變綠色
- **穩定**：選定構圖後目標點固定不動；黃點逐格平滑移動；自動偵測的主體突然跳到別處時，要持續約 1 秒才會換；建議清單不會一直重排
- **點畫面指定主體**：點一下想拍的東西就會鎖定並持續追蹤（模板比對）；點到人臉則鎖定那個人。按「已鎖定主體 ✕」取消
- **裁切預覽**：直接顯示「拍下後會裁成什麼樣子」
- **拍照輸出**：在「取景提示」模式拍，成片就是取景畫面；在「裁切預覽」模式拍，成片是裁切版本。兩種版本都可以另存
- **沒有相機時**：可以分析自己的照片，也有 3 個示範場景（海上日落、霧中孤樹、對稱拱廊）

## 檔案結構

```
web/
  src/
    engine.js    構圖分析引擎（純 JavaScript）
    face.js      人臉偵測（pico）與驗證
    app.js       相機、繪製參考線、互動、拍照
    app.css      介面樣式
    index.html   頁面骨架（build 時把上面三個檔案嵌進來）
  vendor/
    facefinder        pico 人臉模型（build 時嵌入）
    PICO-LICENSE.txt  pico 授權（MIT）
  dist/
    index.html       獨立網頁版（放上任何 HTTPS 主機或 localhost 即可）
    photorium.html   Claude Artifact 版（沒有 <html>/<head> 外殼）
test/
  engine.test.js  引擎單元測試（合成影像）
  ui.test.js      Playwright 介面測試（含模擬相機）
  face.test.js    人臉偵測回歸測試（40 張實拍照片的人工標註）
  face-load.js    測試用：載入 face.js 並嵌入模型
build.js          合併 src → dist
```

## 執行方式

修改 `web/src/` 之後執行：

```bash
node build.js
```

### 在電腦上用網路攝影機

瀏覽器只允許在 `https://` 或 `localhost` 下開啟相機：

```bash
npx serve web/dist
# 打開 http://localhost:3000
```

### 在手機上即時取景

手機必須透過 HTTPS 連線，有兩種方式：

1. **GitHub Pages**（目前使用）：`node build.js` 會同時產生 `docs/index.html`，推到 `main` 後由 GitHub Pages 從 `docs/` 發佈。
2. **臨時通道**：先執行 `npx serve web/dist`，再用 `npx localtunnel --port 3000` 或 `cloudflared tunnel --url http://localhost:3000` 取得 HTTPS 網址。

> 在 Claude 內開啟的 Artifact 版本，瀏覽器不允許即時相機，只能用「照片」功能（手機上可以直接拍一張）和示範場景。

## 用自己的照片測試（HEIC）

iPhone 預設拍 HEIC。Safari 可以直接讀取；Chrome、Edge 這類瀏覽器則會在第一次遇到 HEIC 時，從 CDN 下載解碼器（heic2any，約 1.3 MB）再轉換。

如果網路擋住了解碼器，可以先把照片批次轉成 JPG。這個工具使用系統的 libheif，不需要另外安裝套件：

```bash
python3 tools/heic2jpg.py "<iPhone 照片資料夾>" test-photos --count 40
```

`--count` 會從資料夾中均勻抽樣指定的張數，長邊縮到 2400 px。`test-photos/` 已加入 `.gitignore`，個人照片不會被提交。

## 分析原理（engine.js）

全部在裝置上完成，畫面先縮小到約 160 px 寬再分析：

| 項目 | 方法 |
|---|---|
| 顯著性（哪裡吸引目光） | 全域色彩對比（frequency-tuned）＋局部中央－周邊對比＋邊緣密度＋輕微中心先驗 |
| 主體 | 有人臉時以人物為主體；否則用顯著性門檻 → 連通區域 → 取最強且緊湊的區塊；橫跨畫面的長條（天空亮帶）會逐步提高門檻拆開 |
| 人臉（face.js） | pico 人臉偵測（MIT，模型 234 KB 嵌入頁面、離線可用）：縮半影像掃大臉＋原尺寸掃小臉；再用膚色比例與「眼睛暗帶」驗證，排除車燈、圖案等誤判 |
| 水平線 | 在 −14° 到 +14° 之間搜尋水平邊緣能量最強的直線，同時考慮覆蓋率 |
| 對稱 | 左右鏡像、上下鏡像的亮度差 |
| 線條方向 | 強邊緣的方向分布（水平／垂直／「/」／「\」） |

每種構圖都會計算：

- **適合度分數**：依場景特徵決定，例如左右對稱度高時提高中央對稱的分數
- **目標位置**：主體或水平線應該落在哪裡
- **移動提示**：主體要往左移 → 鏡頭往右
- **裁切框**：保持原比例，讓主體剛好落在目標位置

### 人像構圖

偵測到人臉時，會改用人像專用的構圖：

- **人像三分**：眼睛放在上三分線，人物偏一側，另一側留給視線
- **人像置中**：適合臉大、正對鏡頭的照片（例如自拍）
- **頭肩特寫**：人物在畫面中偏小時，建議靠近一點，或裁切成特寫
- **合照置中**：有 2 人以上時，讓整群人置中、眼睛連成的線放在上三分線

另外有幾種提示：頭頂或下巴被切到、畫面下緣切在脖子、依身體比例推估是否切在膝蓋或腳踝、臉太靠近邊緣，以及合照時每個人的眼睛高度差太多。

在 40 張實拍照片上，4 張有清楚人臉的照片偵測到 3 張，另有 1 張誤判（卡片上的卡通圖案）。漏掉的是低頭吃飯的側臉。執行測試：`node test/face.test.js <rgba 資料夾>`。

### 構圖品質的調整（2026-11-01，依手機實測回饋）

- 目標點會「黏著」：選定的三分點不會因為主體稍微移動就跳到另一個點
- 大的主體不會被硬推到三分點，越大越靠近中央；目標點也不會讓主體被推出畫面
- 裁切會試幾種大小，挑「主體位置準、邊緣不切過物體、保留越多越好」的；主體不確定時只輕微裁切；人像會保住估計的全身
- 水平線判斷更嚴格：上下兩側要明顯不同、接近水平、不貼近畫面上下緣，避免把桌緣、路緣當成水平線

## 已知限制與下一步

- 人臉偵測只認得大致正面、直立的臉，低頭、側臉、背影都偵測不到，這時會退回顯著性判斷。也不認得動物。詳見 [TODO.md](TODO.md)。
- 引導線（道路、欄杆往遠方延伸）目前只用斜線比例粗略判斷，還沒有做消失點偵測。
- 還沒處理前鏡頭（自拍）時移動提示的左右方向。
- 驗證可行後，可以把 `engine.js` 的規則移植到 Flutter 或原生 App（iOS Vision、Android ML Kit）。
